# 仓序业务需求基线

整理日期：2026-10-09；文档提交整理：2026-10-10。状态：需求梳理，待业务验收；不是功能完成声明。

## 1. 目标与范围

服务智算服务器、GPU BOX 和工作站的物料入库、领退料、装配、测试返工、交付、售后和盘点。系统应能够从一台整机追溯实际配件及变更历史，也能够从一块板卡追溯采购来源、装机位置、维修去向和最终交付。

需求依据包括服务器与工作站生产台账、交付及售后台账、采购入库界面，以及当前 InvenTree 源码。台账证明了业务场景，不能单独证明实时库存、完整流转记录或正式审批规则。仓库文档仅保留归纳后的需求，不收录客户、人员、真实序列号和原始生产附件。

首期覆盖一组代表性机型和一个试点仓区，完成从收货到售后的闭环。完整财务核算、税务、全厂排程、产线设备控制不纳入首期。现有 ERP 与仓序的主数据和库存权威边界需要在实施前确定。

## 2. 当前代码能支撑到哪里

以下是源码审阅结论，没有运行服务、执行测试或完成现场验收。表内“补充”描述目标，不代表已经实现。

| 收货 | PurchaseOrder.receive_line_item 支持数量、库位、批次、SN、备注 | ERP 单据关联、附件明细、检验及异常处置、扫码批量核对 |
| 装配与拆卸 | BOM/替代料、BuildItem.install_into、StockItem 安装/拆卸与跟踪记录 | 实际配置版本、槽位、固件、变更原因与配置快照 |

| 交付 | 销售单、多次 SalesOrderShipment、发货/送达时间和物流信息 | 配套清单、装箱校验、配置冻结、客户签收证据与差异处理 |

| 中文与界面 | React 前端、中文翻译、权限与 API | 现场术语、扫码路径、批量操作及不同岗位的可用性验收 |

源码入口：[物料](../../src/backend/InvenTree/part/models.py)、[厂商与供应商](../../src/backend/InvenTree/company/models.py)、[库存](../../src/backend/InvenTree/stock/models.py)、[订单](../../src/backend/InvenTree/order/models.py)、[生产](../../src/backend/InvenTree/build/models.py)、[系统设置](../../src/backend/InvenTree/common/setting/system.py)。

需要特别区分：

- 现有 SN 并非默认全局唯一：数据库有物料与 SN 约束，应用还有物料变体树内校验；不能用裸 SN 作为跨物料唯一键，也不能为导入方便直接关闭约束。
- 必测拦截与退货功能需要核对配置；必测完工拦截不等于完整交付放行。
- 已有测试结果不能证明换件后自动复测；首期必须补上与配置版本关联的有效性判断。
- 客户退货不能直接当作完整的供应商 RMA；供应商维修往返需要明确业务状态及库存位置。

## 3. 角色与工作入口

| 角色 | 主要工作入口 | 权责要求 |
|---|---|---|
| 仓库 | 待收货、待发料、退料、待出库、盘点 | 扫码定位实物与单据；库存调整需理由和追踪 |
| 生产 | 工单、备料、装配、拆件、返工 | 记录实际用料、位置和配置变更，不能凭备注改变库存 |
| 工程/质量 | 规格、批准替代料、测试、问题、放行 | 维护工程规则，核对测试与配置，处理缺测/失败/偏离 |
| 售后 | 客户服务单、供应商送修、收回与换件 | 逐件跟踪去向，区分修复、替换、未返回和报废 |
| 销售/交付 | 订单、分批发货、装箱、签收 | 商机、订单、发货事实分开，允许部分交付 |
| 管理员/主管 | 主数据、权限、导入复核、审计 | 权限最小化；对审批分工和例外规则作明确配置 |

角色可以兼任，具体审批链待业务确认；不能默认每次扫描都需要审批。

## 4. 首期必须具备的需求

下表的“首期”是投入生产前的业务目标，并不意味着每项都要新写模型；先复用原有能力，再补实证缺口。

### 4.1 物料、身份与制造来源

| 编号 | 需求 | 验收标准 |
|---|---|---|
| MD-01 | 管理内部料号、ERP 编码、制造商料号、OEM/客户别名及适用范围 | 扫码或任一别名能定位唯一候选或提示歧义；保留前导零，不静默合并冲突 |
| MD-02 | 区分设计型号、BOM 修订、制造批次、实物 SN 与内部实物 ID | 同一批次多件可逐件追溯；型号/批次/实物不混用；跨物料重号按命名范围复核 |
| MD-03 | 记录 PCB、SMT、板卡制造、供应商等角色及批次关联 | 能按某加工方及批次定位受影响实物；OEM 别名不能自动当作制造商 |
| MD-04 | 按类别定义可维护的技术参数和追踪方式 | GPU、底板、交换板、线缆、结构件等有不同模板；支持逐件 SN、批次数量及内部编号 |
| MD-05 | 维护带版本的标准 BOM、批准替代料及标准附件清单 | 订单/工单采用的版本可追溯；实际替代有依据；历史清单不随模板更新而改变 |

行业分类至少覆盖：CPU、DIMM、GPU/加速器、GPU 底板、PCIe Switch/交换板、NVLink/NVSwitch 类互联部件、NIC/HCA/DPU、以太网/InfiniBand 交换机、Riser/Retimer、NVMe/背板、PSU/PDB、风扇/散热/液冷、机箱/结构件及包装附件。

交换部件须兼容博通、联瑞及其他国内外厂商的实际产品资料；分别存储芯片厂商、板卡品牌/制造商、供应商、设备类别与协议。不能将所有 switch 归为 NVSwitch，也不能假定某品牌只生产一种协议设备。具体型号、参数和兼容关系由工程资料与签核确定。

线缆至少区分 GPU 供电线束、PCIe/MCIO 等内部高速线、互联线、DAC/AOC、光纤、RJ45/管理线和分支线。记录连接器、长度、方向/分支、数量单位及适用范围；需要连接追溯的无厂商 SN 线缆可以生成内部实例号。仅凭名称中的型号字符串不能认定芯片类型或性能规格。

### 4.2 入库与领退料

| 编号 | 需求 | 验收标准 |
|---|---|---|
| IN-01 | 收货关联采购、项目、外部单据、物料、批次、数量、SN、仓库/库位 | 序列化数量与实收 SN 数一致；支持部分收货；重复提交不重复入账 |
| IN-02 | 收货检验、隔离及差异处理 | 不合格/待检件不能按可用件领用；少到、多到、错料各有记录及处置 |
| IN-03 | 随货配套物独立明细或明确套件组成 | “板卡附线缆”明确是每套数量还是整单数量；未确认前不自动拆分库存 |
| MAT-01 | 按工单备料、预留、分批领料及交接 | 能区分缺料、已预留、已领未装和已装；并发领用不能占用同一实物 |
| MAT-02 | 余料退库、故障拆回、返工领料分别记录 | 每次移动有来源/目标、关联工单和操作者；拆件后整机配置及实物位置一致 |

### 4.3 单机装配、质量与返工

| 编号 | 需求 | 验收标准 |
|---|---|---|
| MFG-01 | 每台整机记录实际配置，包括配件身份、位置、批次及固件版本 | 可由整机查询实装配件，由配件查询所在整机；未采集的信息标记未知 |
| MFG-02 | 安装、拆卸、替换产生配置版本与不可覆写历史 | 同一配件不能同时装入两台机器；位置冲突被拦截；可还原交付时配置 |
| MFG-03 | 支持不同主控/CPU 架构、无头配置和经批准的实际差异 | 标准 BOM 与实际配置可对照；配置偏离有批准依据，不能只靠自由备注 |
| QC-01 | 质量问题关联机型/批次/单机/部件及证据 | 故障现象、环境、复现、严重性、责任人、处置、复核记录完整 |
| QC-02 | 临时措施、永久改进与返工任务分开管理 | 测试通过但仍缺结构件/需返工的机器不能自动视为可交付；关闭有验证证据 |
| QC-03 | 测试记录绑定实际配置版本、测试项目、结果和附件 | 换件、固件或接线变更后，按工程规则使受影响测试失效并生成复测要求 |
| QC-04 | 交付放行校验质量、配置、测试与附件齐套 | 失败、缺测、未处理的阻断问题或必需附件缺失时拦截；例外须具备权限、理由与审计 |

质量问题状态建议：待确认 → 处理中 → 待验证 → 已关闭，可重新打开。完工、测试通过、质量问题关闭、交付放行应是不同事实。

### 4.4 出库、装箱与签收

| 编号 | 需求 | 验收标准 |
|---|---|---|
| OUT-01 | 商机、订单、出库记录分离；销售交付与售后寄件区分 | 商机/预付款记录不会生成出库事实；历史备注不能直接触发库存扣减 |
| OUT-02 | 复用销售单多批次发货，按行记录计划、已发、未发 | 同一订单跨月分批发机器和 GPU 时逐行核算；不能用一个总数量混加不同计量对象 |
| OUT-03 | 装箱扫码核对整机、板卡、线缆、附件与包装 | 缺件/错件/重复扫码可识别；生成箱单并绑定当次交付配置快照 |
| OUT-04 | 记录物流、签收凭证、实际收货差异与补发 | 发货与签收分开；部分签收/短缺有后续任务，单据可关联但不重复出库 |

### 4.5 客户售后与供应商维修

| 编号 | 需求 | 验收标准 |
|---|---|---|
| RMA-01 | 服务单包含多个物料行、故障、原设备和附件证据 | 一块板加多根线可在同一单中逐行处理；每行独立数量、SN/批次和处置结果 |
| RMA-02 | 区分客户退回、在厂故障、供应商送修和维修返还 | 任一时刻能查保管方、位置、送收时间及关联物流；外送不能误当销售收入或采购新品 |
| RMA-03 | 供应商原件修复、新件替换、部分返还、报废及未返回闭环 | 旧 SN 与新 SN 有显式替换关系；新件入库不覆盖旧件历史；未返数量持续可查 |
| RMA-04 | 维修收回隔离、检验、重新装机及复测 | 未检维修件不可直接放行；从原设备拆出到替换件装回形成完整追踪链 |
| RMA-05 | 客户所有、企业所有及代管物料明确区分 | 物理保管地点与所有权分开；避免将客户退修件自动计为可销售自有库存 |

维修行状态建议：待处理 → 待寄出 → 外送中 → 对方已收 → 维修中 → 待返还 → 已收待检 → 已结案；允许部分数量处于不同状态。结案需要所有明细有明确结果，而不是主单填写“已处理”。

### 4.6 盘点与库存核实

| 编号 | 需求 | 验收标准 |
|---|---|---|
| INV-01 | 盘点任务明确范围、时点、参与人和期间移动处理方式 | 区分仓库、工位、临时存放区、在制品和外送维修；选定冻结或移动对账策略 |
| INV-02 | 差异调查、复盘/复核后调整 | 漏扫、账外物、缺件、位置错、已装未登记分别处理；未确认差异不直接改账 |
| INV-03 | 历史账面、待核实、实盘确认分开标记 | Excel 行数不能当库存余额；开账需确认期初实物及未结业务，保留核实依据 |

## 5. 导入与现有 ERP 衔接

| 编号 | 需求 | 验收标准 |
|---|---|---|
| DATA-01 | 导入暂存区保留源文件标识、工作表、行/单元格定位、原值与转换结果 | 可逐条预览、审核、拒绝及追溯；正式业务写入前不改变库存 |
| DATA-02 | 编码、SN、日期、数量和单位校验 | 前导零不丢失；缺年日期不猜年份；SN 区间与数量不符时挂起，不自动补造实物 |
| DATA-03 | 去重与歧义处理 | 总表/明细表重复、料号冲突、混合出库、备注与状态不一致进入复核，不静默覆盖 |
| DATA-04 | 图片和附件导入 | 解析嵌入图片及关联；DISPIMG 公式不当作图片，失效引用和错误值可报告并保留来源 |
| DATA-05 | 导入幂等、失败恢复和更正 | 同一导入批次重试不重复建单/计数；允许部分失败报告；已生效库存更正通过可追溯业务操作 |
| INT-01 | ERP 外部单据/行与内部对象显式映射 | 区分来源系统、单据类型、编号、行号及版本；重复回传只处理一次 |
| INT-02 | 明确各对象的主数据权威与同步方向 | 对采购、料号、仓库、库存、出库分别确定主系统；更正/撤销/冲突能对账，不双写两套独立余额 |

历史迁移顺序：清理物料与编码 → 确认期初库存及实物 → 导入未结采购/工单/订单/维修 → 关联历史追溯档案 → 对账。只有资料充分、业务已确认的历史事件才参与库存重建。

## 6. 交互与运行要求

| 编号 | 需求 | 验收标准 |
|---|---|---|
| UX-01 | 中文术语、状态与错误信息一致；保留原版可用页面 | 仓管、生产、售后分别完成典型任务，无需理解底层模型名 |
| UX-02 | 高频流程支持扫码、连续录入、批量预览和明确反馈 | 错码/重码不静默跳过；焦点稳定；断网/超时可辨别是否生效，重试不重复记账 |
| UX-03 | 一处查询料号/SN/订单并查看完整履历 | 歧义时选择正确物料；显示库存、装机、外送、交付和质量记录及时间 |
| OPS-01 | 权限、审计和附件访问控制 | 库存/质量/维修更改记录操作者、时间、原因、前后值及关联单据；无权限者无法绕过接口 |
| OPS-02 | 并发和事务一致性 | 并发抢同件、重复收货、半途失败不会制造重复库存或断裂配置；冲突可恢复 |

| OPS-04 | 数据规模、性能和设备适配 | 试点前确认物料/SN/附件量、并发人数、扫码枪/打印机及网络条件，约定可测的响应和恢复目标 |

## 7. 实现边界与候选扩展

正式实体名、字段和接口在后续技术设计中确认；此处用于界定业务责任，不要求每个名词都建独立表。

| 候选扩展 | 业务责任 | 必须引用的已有基础 |
|---|---|---|
| 编码映射、制造批次及加工角色 | MD-01～MD-03 的别名、来源和冲突管理 | Part、Company、ManufacturerPart、SupplierPart、StockItem |
| 单机配置版本、安装位置及替换记录 | MFG-01～MFG-03、换件历史、交付快照 | StockItem、Build、BOM、现有安装/拆卸动作 |
| 质量问题、返工任务、测试有效性和放行 | QC-01～QC-04 | 测试结果、附件、工单与配置版本 |
| 服务单、供应商维修及物料处置行 | RMA-01～RMA-05 | 客户退货、库存、公司与物流关联 |
| 装箱核对、签收证据 | OUT-03～OUT-04 | 销售单及 SalesOrderShipment |
| 盘点任务与差异复核 | INV-01～INV-03 | 库位、StockItem.stocktake 与库存跟踪 |
| 导入暂存和外部单据映射 | DATA-01～INT-02 | 现有导入/API 能力与上述业务对象 |

InvenTree 继续负责库存数量、预留、位置和流转事实；扩展引用同一实物，不新建另一套库存余额。所有权及外送保管状态需要与核心库存可用性规则一致。优先配置、参数模板及插件扩展；插件承载不了的权限、事务或生命周期逻辑再评估最小核心改动。

## 8. 交付顺序与后续范围

本文件基于实际业务资料更新优先级；与早期 [改造规划](ROADMAP.zh-CN.md) 的阶段顺序不一致时，以本节为当前业务排序。[行业模型设计](DOMAIN-MODEL.zh-CN.md) 仍是候选技术设计，不是已实现模型清单。

1. **确认与试用**：锁定稳定基线，配置中文、角色、库位、必测规则；用脱敏样例验证现有入库/领退料/装配/出库，确定 ERP 权威边界及导入规则。
2. **业务闭环**：优先编码与批次、实际配置及换件、质量返工、供应商维修、分批交付和装箱、导入复核与盘点差异。已有功能满足的直接复用。
3. **生产试点**：完成下节全部验收及数据对账，训练操作员，验证扫码打印、权限、备份恢复和升级，再扩大机型/仓区。
4. **深化工程能力**：完整 PCIe/GPU/网络拓扑、多端线缆、自动硬件检测、工程签核的兼容规则。首期保留必要分类、位置和接口扩展点，无需等待完整拓扑图才能使用仓管。
5. **智能体增强**：Pi、手册/故障知识检索、实时库存查询、缺料分析和业务草稿；向量库只作知识索引。数量、权限及操作结果以业务系统为准，变更走受控业务工具。它不替代库存模型和质量规则。

不承诺当前代码已开箱满足全部场景，也不在需求阶段给出未经估算的工期。

## 9. 首期端到端验收用例

使用虚构数据编制可重复的验收集，分别记录通过、失败与证据。以下均为待执行要求。

| 用例 | 操作与预期 |
|---|---|
| AC-01 收货 | 同一采购单分两次收货；逐件 SN、批次和随货附件一致，重复请求不增库存 |
| AC-02 编码冲突 | 同名不同件、跨物料同 SN、OEM 别名、前导零编码可正确区分，歧义阻止自动落账 |
| AC-03 领退料 | 两人同时领同一件只能成功一次；余料退回、故障拆回有各自位置与状态 |
| AC-04 装机换件 | 记录位置和配置版本；换件保留旧件去向，旧配置和原测试仍能查到但不能充当新配置合格证据 |
| AC-05 质量放行 | 测试通过但存在未闭合阻断返工/缺附件时不能放行；复测及关闭后才能生成放行记录 |
| AC-06 供应商维修 | 板卡与线缆同单外送，部分原件返还、部分新 SN 替换；每行数量守恒、未返清晰、旧新关联完整 |
| AC-07 分批交付 | 整机与 GPU 不同批发货，未发余额按物料行计算；装箱、交付快照及签收证据能回查 |
| AC-08 客户返修 | 已交付设备退回隔离、拆件送修、收回复测再发；原销售、服务和两次配置可串联 |
| AC-09 盘点 | 临时库位、已装配件和外送物料正确归属；差异调查前不自动调整，复核后仅记一次 |
| AC-10 历史导入 | 缺年日期、SN 区间数量冲突、料号冲突、混合物料行和图片错误进入复核；重导无重复记录 |
| AC-11 外部同步 | ERP 单据重复、乱序更新或撤销不双计库存；冲突可定位并对账 |
| AC-12 权限与恢复 | 无权放行/调整被拒；中断重试可恢复；数据库和附件恢复后上述链路仍完整 |

生产准入：上述用例通过，库存与配置关键约束无已知失败，阻断问题关闭，业务负责人完成验收。完成需求文档不等于完成该验收。

## 10. 实施前待确认事项

以下不阻碍当前需求整理，但对应实现或导入前必须确认，不能由程序猜测。

| 事项 | 需要确认的决策 |
|---|---|
| ERP 分工 | 各主数据、采购、出入库、库存由谁主写；可用 API/导出格式和撤销规则 |
| 物料与 SN | 料号冲突裁定、OEM 别名范围、SN 唯一范围及无 SN 件追踪等级 |
| 套件与附件 | 随货线缆按套还是按单计量；哪些附件有库存、哪些只作包装检查 |
| 工程规则 | 代表性 BOM、允许替代、位置/接口规范、换件/固件变更后的复测范围 |
| 放行与审批 | 阻断问题、例外放行、报废、盘盈亏的权限与责任分工 |
| 售后边界 | 自有/客户/代管所有权、供应商中转、保修和维修费用记录需求 |
| 历史开账 | 可信期初时点、未结业务和实盘确认人；不完整历史只作档案还是补录事件 |
| 现场规模 | 用户及并发数、库区数量、记录量、扫码打印设备、内网部署和备份目标 |

后续实施应先把这些决策形成版本化记录，再细化任务和排期。本轮到此为止，不创建业务数据、不改动业务代码。
