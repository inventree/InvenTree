## 1. 目标与范围

服务智算服务器、GPU BOX 和工作站的物料入库、领退料、装配、测试返工、交付、售后和盘点。系统应能够从一台整机追溯实际配件及变更历史，也能够从一块板卡追溯采购来源、装机位置、维修去向和最终交付。

需求依据包括服务器与工作站生产台账、交付及售后台账、采购入库界面，以及当前 InvenTree 源码。台账证明了业务场景，不能单独证明实时库存、完整流转记录或正式审批规则。仓库文档仅保留归纳后的需求，不收录客户、人员、真实序列号和原始生产附件。

首期覆盖一组代表性机型和一个试点仓区，完成从收货到售后的闭环。完整财务核算、税务、全厂排程、产线设备控制不纳入首期。试点库存唯一账本已确定为 InvenTree/仓序；采购单、物料主数据及其他 ERP 对象的权威边界仍需确认。

## 2. 当前代码能支撑到哪里

下表先总结 InvenTree 上游原生能力和业务缺口。它不是当前分支的逐项验收表。

| 业务 | 已有基础 | 本项目需配置、补充或验证 |
|---|---|---|
| 物料与采购 | Part、分类参数、ManufacturerPart、SupplierPart、采购单与项目代码 | 企业编码/OEM 别名映射、制造批次及 PCB/SMT 等加工角色 |
| 收货 | PurchaseOrder.receive_line_item 支持数量、库位、批次、SN、备注 | ERP 单据关联、附件明细、按已确认规则隔离/检验/异常处置、扫码批量核对 |
| 装配与拆卸 | BOM/替代料、BuildItem.install_into、StockItem 安装/拆卸与跟踪记录 | 实际配置版本、槽位、固件、变更原因与配置快照 |
| 测试 | StockItemTestResult、测试附件与测试站、必测完工拦截设置 | 配置变更影响哪些测试、旧结果失效、返工闭环与交付放行 |
| 交付 | 销售单、多次 SalesOrderShipment、发货/送达时间和物流信息 | 配套清单、装箱校验、配置冻结、客户签收证据与差异处理 |
| 售后 | ReturnOrder 面向客户退货，支持收货隔离和处置结果 | 供应商送修/返还、多物料售后单、部分返还、旧新 SN 替换及保管位置 |
| 盘点 | StockItem.stocktake 与库存调整记录 | 盘点任务、差异调查、复核、交接和关闭条件 |
| 中文与界面 | React 前端、中文翻译、权限与 API | 现场术语、扫码路径、批量操作及不同岗位的可用性验收 |

当前开发分支新增了 `cangxu` Django App 和后续迁移，复用原生 Part、StockItem、采购/销售单和 Build 数据。已建别名、制造批次及批次伙伴、单机配置与换件、质量问题/返工、售后服务事件、盘点会话、发货清单，以及导入批次/行暂存模型和 API。导入支持 XLSX 多工作表解析（保留单元格坐标、原始值、类型和格式，文件不作为附件保存）、常见中英文字段的保守提示映射、JSON 批量暂存、原值与转换值追溯、校验、逐行拒绝和审批；重复表头会标为歧义，未知列保留原值，不据此自动建物料或库存。开账行可按精确 IPN/已登记别名映射到现有物料，并要求操作人明确指定内部库位；冲突或多物料命中进入复核。只有设置期初日期并确认已实盘的开账库存批次，审核后才能写入原生库存和制造批次。试点期库存权威已确认由 InvenTree/仓序承担。采购、出库、售后及物料历史当前只可暂存，不会自动落账。图片/附件提取及业务专用列映射尚未完成。制造批次可关联采购明细；客户退货可关联原销售发货单，收货后进入待检库存。硬件规格修订、端口定义和多端线缆端点已有基础模型/API，相关类别、协议、字段和校验提示已有简体中文后端词条。前端现有仓序工作台入口，提供常用原生收货/生产/库存/交付页面导航，以及按序列号或料号查询库存实物并打开 InvenTree 原生实物历史；该页面是流程入口和追溯搜索，不代表全流程已完成仓序化。物料领料/退料表单和发货签收/差异跟进表单已接入；入库、装配、售后等专用表单仍未完成。领退料界面已有虚构 API 响应的 Chromium 冒烟记录；签收界面已通过生产构建，并在隔离组件浏览器测试中验证部分签收、损坏差异登记和关闭，真实发货详情页、后端联调及业务操作员验收仍待完成。InvenTree 对手机视口显示通用“手机视图未优化”提示，故移动端体验尚未验收。完整整机拓扑、兼容规则、参数化 BOM/替代审批及其余仓序专用业务表单仍未实现。

虚构演示命令覆盖 42 个示例物料及 K20/K10 服务器、K2/K4 工作站虚构系列（只借用工作簿中的系列标签，不代表真实 BOM），包括 PCIe 转接板、盲插板、中置板、推理板、风扇板、显示板、GPU、PCIe Switch 与多类线缆；另生成 20 个硬件规格草稿、7 个交换端口和 16 个线缆端点，均明确标记为待工程资料确认。目录包含 Broadcom PEX89048 芯片、Microchip Switchtec PFX PM50100B1-FEI 芯片和联瑞 LR-LINK LRSV9500-4I 成品卡公开资料样例，用于区分芯片厂商、板卡制造商和品牌；对应仓序 IPN 为虚构值，新型号不生成任何演示库存，不能据此认定本公司采购、兼容或放行。公开资料：[Broadcom PEX89048](https://www.broadcom.com/products/pcie-switches-retimers/expressfabric/gen5/pex89048)、[Microchip PFX Gen5](https://ww1.microchip.com/downloads/aemDocuments/documents/DCS/ProductDocuments/Brochures/00003776D.pdf)、[联瑞 LRSV9500-4I](https://www.lr-link.com.cn/productshow/LRSV9500-4I.html)。来源工作簿只在本地汇总结构与计数：交付明细 52 行中状态桶为已完成 41、待发/处理中 8、其他 1、空缺 2；售后明细 16 行、生产问题明细 33 行。生成器仅使用约五分之四完成发货的比例及 16/33 行数作为虚构记录乘数；客户、内部料号、SN、人员、问题描述、单据编号和交易明细均重新生成，原始行未上传或写入开发库。2026-10-12 在 pro6000D 独立开发库将虚构数据扩展至 `--scale-factor 30`：14,496 件库存、1,201 台配置整机、961 个已签收包裹、240 个待发包裹、31 条虚构签收异常、480 条客户退货、480 条供应商/内部维修案例、990 条生产质量问题；生成器同时核对 14,496 条批次关联。SQLite 完整性检查为 `ok`，所有记录均由虚构身份和交易内容构成。客户签收不重复改变 InvenTree 库存。每倍系数仍按固定规则扩展客户退货和生产问题案例。首件样例通过 InvenTree 原生 Build/BOM、领料分配、输出完工和配置槽位登记形成生产追踪；其余配置数据明确是演示装配，不等同于真实工单。批次关联按实物当前物料和批次幂等校准，每件演示实物只对应一个批次。没有把原始企业台账、真实 SN、客户、人员或附件写入仓库，也没有把演示厂商/型号关系当作工程兼容结论。

当前 API 回归测试覆盖代表性的部分收货与批次关联、原生 Build 输出与配置登记、配置换件、配置件拆回、返工任务关联的数量物料安装、普通耗材领料/部分退料幂等、客户退货、供应商维修、质量返工、盘点和分批装箱步骤；它们尚未覆盖所有 AC 用例。XLSX 上传/来源坐标暂存和物料目录、采购、出库、售后记录的基础分类型字段校验已有虚构数据 API 测试；除期初库存外，历史类型仍不支持审批后落账。用户提供的原始工作簿尚未上传或导入开发库，完整字段映射、真实数据复核与历史单据落账仍未完成。MAT-02 的完整工单关闭和现场领退料验收、完整 ERP 对账、全量工程拓扑、正式放行、生产数据库并发/恢复及现场 UX 验收仍未完成。第 9 节验收用例继续作为生产准入目标。

需要特别区分：

- 现有 SN 并非默认全局唯一：数据库有物料与 SN 约束，应用还有物料变体树内校验；不能用裸 SN 作为跨物料唯一键，也不能为导入方便直接关闭约束。
- 必测拦截与退货功能需要核对配置；必测完工拦截不等于完整交付放行。
- 已有测试结果不能证明换件后自动复测；首期必须补上与配置版本关联的有效性判断。
- 客户退货不能直接当作完整的供应商 RMA；供应商维修往返需要明确业务状态及库存位置。

| 角色 | 主要工作入口 | 权责要求 |

| 仓库 | 待收货、待发料、退料、待出库、盘点 | 扫码定位实物与单据；库存调整需理由和追踪 |

| 工程/质量 | 规格、批准替代料、测试、问题、放行 | 维护工程规则，核对测试与配置，处理缺测/失败/偏离 |
| 售后 | 客户服务单、供应商送修、收回与换件 | 逐件跟踪去向，区分修复、替换、未返回和报废 |
| 销售/交付 | 订单、分批发货、装箱、签收 | 商机、订单、发货事实分开，允许部分交付 |
| 管理员/主管 | 主数据、权限、导入复核、审计 | 权限最小化；对审批分工和例外规则作明确配置 |

角色可以兼任，具体审批链待业务确认；不能默认每次扫描都需要审批。

## 4. 首期必须具备的需求

### 4.1 物料、身份与制造来源

| 编号 | 需求 | 验收标准 |
|---|---|---|
| MD-01 | 管理内部料号、ERP 编码、制造商料号、OEM/客户别名及适用范围 | 扫码或任一别名能定位唯一候选或提示歧义；保留前导零，不静默合并冲突 |
| MD-02 | 区分设计型号、BOM 修订、制造批次、实物 SN 与内部实物 ID | 同一批次多件可逐件追溯；型号/批次/实物不混用；跨物料重号按命名范围复核 |
| MD-03 | 记录 PCB、SMT、板卡制造、供应商等角色及批次关联 | 能按某加工方及批次定位受影响实物；OEM 别名不能自动当作制造商 |

交换部件须兼容博通、联瑞及其他国内外厂商的实际产品资料；分别存储芯片厂商、板卡品牌/制造商、供应商、设备类别与协议。不能将所有 switch 归为 NVSwitch，也不能假定某品牌只生产一种协议设备。具体型号、参数和兼容关系由工程资料与签核确定。

线缆至少区分 GPU 供电线束、PCIe/MCIO 等内部高速线、互联线、DAC/AOC、光纤、RJ45/管理线和分支线。记录连接器、长度、方向/分支、数量单位及适用范围；需要连接追溯的无厂商 SN 线缆可以生成内部实例号。仅凭名称中的型号字符串不能认定芯片类型或性能规格。

## 5. 导入与现有 ERP 衔接

首期试点决策（2026-10-12确认）：InvenTree/仓序是试点库存唯一业务账。ERP 导入先进入暂存区供预览、校验和审核；审核通过的库存事实写入 InvenTree 原生物料、订单和库存对象，ERP 不得并行回写库存余额。来料检验需记录并归档；收货时可选隔离，默认进入可用库存；被隔离的库存由质检员检验后放行，不合格处置需审批。该流程仍待功能实现和业务验收。采购单、物料主数据及其他对象的权威和正式同步方向仍待确认。

| 编号 | 需求 | 验收标准 |
|---|---|---|
| DATA-01 | 导入暂存区保留源文件标识、工作表、行/单元格定位、原值与转换结果 | 可逐条预览、审核、拒绝及追溯；正式业务写入前不改变库存 |
| DATA-02 | 编码、SN、日期、数量和单位校验 | 前导零不丢失；缺年日期不猜年份；SN 区间与数量不符时挂起，不自动补造实物 |
| DATA-03 | 去重与歧义处理 | 总表/明细表重复、料号冲突、混合出库、备注与状态不一致进入复核，不静默覆盖 |
| DATA-04 | 图片和附件导入 | 解析嵌入图片及关联；DISPIMG 公式不当作图片，失效引用和错误值可报告并保留来源 |
| DATA-05 | 导入幂等、失败恢复和更正 | 同一导入批次重试不重复建单/计数；允许部分失败报告；已生效库存更正通过可追溯业务操作 |
| INT-01 | ERP 外部单据/行与内部对象显式映射 | 区分来源系统、单据类型、编号、行号及版本；重复回传只处理一次 |
| INT-02 | 明确各对象的主数据权威与同步方向 | 对采购、料号、仓库、库存、出库分别确定主系统；更正/撤销/冲突能对账，不双写两套独立余额 |

历史迁移顺序：清理物料与编码 → 确认期初库存及实物 → 导入未结采购/工单/订单/维修 → 关联历史追溯档案 → 对账。只有资料充分、业务已确认的历史事件才参与库存重建。

## 8. 交付顺序与后续范围

本文件基于实际业务资料更新优先级；与早期 [改造规划](ROADMAP.zh-CN.md) 的阶段顺序不一致时，以本节为当前业务排序。[行业模型设计](DOMAIN-MODEL.zh-CN.md) 仍是候选技术设计，不是已实现模型清单。

2026-10-13 优先级调整：常驻工作伙伴作为接下来的独立工作流推进，知识与运行底座可和业务闭环并行，具体执行工具依赖各业务规则及验收。下列业务阶段保留原责任；第 5 项不再表示必须等完整拓扑完成后才启动助手。不得用只读聊天壳替代助手第一版。

1. **确认与试用**：锁定稳定基线，配置中文、角色、库位、必测规则；用脱敏样例验证现有入库/领退料/装配/出库，确定 ERP 权威边界及导入规则。
2. **业务闭环**：优先编码与批次、实际配置及换件、质量返工、供应商维修、分批交付和装箱、导入复核与盘点差异。已有功能满足的直接复用。
3. **生产试点**：完成下节全部验收及数据对账，训练操作员，验证扫码打印、权限、备份恢复和升级，再扩大机型/仓区。
4. **深化工程能力**：完整 PCIe/GPU/网络拓扑、多端线缆、自动硬件检测、工程签核的兼容规则。首期保留必要分类、位置和接口扩展点，无需等待完整拓扑图才能使用仓管。
5. **常驻工作伙伴（并行推进）**：按 AI-01～AI-12 建设 Pi Durable 常驻运行、简洁独立对话、全流程知识、实时查询、主动事件/定时工作和授权执行；首期推荐打通入库归档职责。知识索引不替代业务账，所有写入走受控业务工具。实施顺序与交接见[技术规划](ASSISTANT-TECHNICAL.zh-CN.md)。

## 9. 首期端到端验收用例

使用虚构数据编制可重复的验收集，分别记录通过、失败与证据。以下均为待执行要求。

| 用例 | 操作与预期 |
|---|---|
| AC-01 收货 | 同一采购单分两次收货；逐件 SN、批次和随货附件一致，重复请求不增库存 |
| AC-02 编码冲突 | 同名不同件、跨物料同 SN、OEM 别名、前导零编码可正确区分，歧义阻止自动落账 |
| AC-03 领退料 | 两人同时领同一件只能成功一次；余料退回、故障拆回有各自位置与状态 |
| AC-04 装机换件 | 记录位置和配置版本；换件保留旧件去向，旧配置和原测试仍能查到但不能充当新配置合格证据 |
| AC-05 质量放行 | 测试通过但存在未闭合阻断返工/缺附件时不能放行；复测及关闭后才能生成放行记录 |
| AC-06 供应商维修 | 板卡与线缆同单外送，部分原件返还、部分新 SN 替换；每行数量守恒、未返清晰、旧新关联完整 |
| AC-07 分批交付 | 整机与 GPU 不同批发货，未发余额按物料行计算；装箱、交付快照及签收证据能回查 |
| AC-08 客户返修 | 已交付设备退回隔离、拆件送修、收回复测再发；原销售、服务和两次配置可串联 |
| AC-09 盘点 | 临时库位、已装配件和外送物料正确归属；差异调查前不自动调整，复核后仅记一次 |
| AC-10 历史导入 | 缺年日期、SN 区间数量冲突、料号冲突、混合物料行和图片错误进入复核；重导无重复记录 |
| AC-11 外部同步 | ERP 单据重复、乱序更新或撤销不双计库存；冲突可定位并对账 |
| AC-12 权限与恢复 | 无权放行/调整被拒；中断重试可恢复；数据库和附件恢复后上述链路仍完整 |

生产准入：上述用例通过，库存与配置关键约束无已知失败，阻断问题关闭，业务负责人完成验收。完成需求文档不等于完成该验收。

助手专项验收另见[AI-AC-01～AI-AC-16](ASSISTANT-TECHNICAL.zh-CN.md#12-验收场景与证据)，当前全部待执行。助手上线除专项验收外，还必须满足所开放动作对应的上述业务用例，不能以助手测试代替业务验收。
