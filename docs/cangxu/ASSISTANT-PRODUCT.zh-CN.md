# 仓序工作伙伴：产品规划

日期：2026-10-13。状态：产品方向已由用户确认；已推进 S2 工具、assistant-ui 对话附件与真实链路开发，阶段证据见[实施记录](ASSISTANT-IMPLEMENTATION.zh-CN.md)。完整产品尚未实现或业务验收。

关联：[业务需求与验收](REQUIREMENTS.zh-CN.md) · [技术规划与实施交接](ASSISTANT-TECHNICAL.zh-CN.md)。需求编号、验收条件与未决业务规则以需求基线为准。

## 1. 已确认的产品决定

仓序需要一个基于 Pi Durable、常驻运行的长期工作伙伴。它掌握网站使用方法与完整业务流程知识，能够接受命令、查询业务事实，在授权范围内自主执行和持续推进工作。用户不打开网站、不发送消息时，它仍能响应业务变化和定时检查。

2026-10-13 最新界面确认：用户提供消息应用式工作台截图，明确此前业务导航下的单栏页不符合要求。本次截图取代原“单栏、不设侧栏”的布局约定：独立深色工作台，左侧伙伴列表、搜索与新建，右侧当前伙伴的连续对话、顶部名称和底部固定输入条；保留业务页面右下角入口。截图中的示例人名、英文角色和桌面窗口控制不是业务数据或浏览器功能要求。

以下决定不可在实施时擅自改回：

- 主界面是独立全屏双栏工作台；左侧是伙伴选择，不是任务看板，右侧持续对话是主要工作区域。
- 不做“正在推进、需要你处理、新发现与结果、长期职责”等首页分区，也不做任务看板或默认三栏工作台。
- 对话区默认不铺满计划卡、工具调用、执行日志、统计数字和快捷建议。
- 常驻运行、主动触发、持久状态与任务恢复属于第一版核心能力，不能推迟到“聊天功能完成后”的远期版本。
- 后台可以有任务、职责、计划和队列；这些结构按需通过对话或简短操作详情呈现，不要求用户先学习任务管理界面。
- 保留原业务页面及其操作能力，助手不可用时仍可办理业务。

## 2. 用户看到的界面

### 2.1 独立对话页

建议主导航名称“工作伙伴”，页面路径暂定 `/assistant/`。名称和路径属于实施建议，允许在不改变已确认形态的前提下细化。

工作台保留以下区域：

| 位置 | 内容 | 约束 |
|---|---|---|
| 左侧 | 伙伴头像、名称、最近消息/交办、时间、搜索、新建及当前账号 | 真实伙伴记录；选中态明确；不放任务统计或职责看板 |
| 顶部 | 当前伙伴名称、简洁状态、历史/更多入口、返回业务页面 | 不出现工作量仪表盘；状态反映后台实际可用性 |
| 中部 | 连续对话、必要的图片、业务记录引用及操作结果 | 单列阅读；过程默认折叠；消息可追溯 |
| 底部 | 输入框、附件入口、已引用业务对象 | 支持多行输入；草稿保留；引用可移除 |
| 按需展开 | 历史查找、重命名、操作详情与个人设置 | 默认收起；不增加独立授权步骤 |

空白页使用一句简短招呼和输入框。已有历史时恢复原对话位置或定位首条未读消息，不每天重新生成欢迎页。助手回答过程中允许用户继续补充；明确区分补充本次工作和新目标，歧义时用一句话澄清。

一名用户保留一个默认伙伴，允许按需创建多个命名伙伴；每个伙伴拥有独立的 Pi 持久会话、历史、附件和草稿，切换不会停止后台任务；菜单停止操作只作用于选中伙伴。已有默认伙伴的标识和历史升级后保留。不得把同一份历史套上不同标题伪装为多个伙伴，也不在生产页面放虚构伙伴和消息。后台多个业务任务可并行存在；它们产生的消息应带简短的业务对象引用，避免不同订单的结果混淆。可以查找历史，不把“新建对话”作为每次交办的前置步骤。不得把一份无限增长的完整历史每次全部发送给模型。

### 2.2 右下角入口

- 全站登录后的业务页面显示轻量助手图标；有需要关注的新消息时显示未读提示。
- 点击进入同一个独立对话页；在对话页内隐藏重复的悬浮入口。
- 从业务页面进入时，可以携带该页面对象的引用，例如采购单或工单。发送前在输入框上方显示引用标签，用户可删除。
- 仅打开页面不自动发送命令，也不自动授权写入；页面切换不改变已经执行中的任务对象。
- 原业务页面的返回位置保留。入口不遮挡提交按钮、扫码输入或移动端安全区域，不抢焦点。

### 2.3 回复与操作的表达

通常使用短文本加记录链接。查询大量记录时才使用表格；涉及人工选择、签字或审批时，在对应消息内显示必要按钮。工程细节、工具名称与完整执行日志默认隐藏。

例如，以下为虚构场景文案：

> 昨天那批收货的照片已经补齐。我已关联到收货记录，还有一份仓管签字待补充。[查看收货记录]

只有后端确认附件关联成功才能说“已关联”；照片齐全不等于验收完成。用户问“刚才做了什么”时，可展开实际操作、时间、数量、执行者和业务回执。

2026-10-13 用户确认：对话组件采用 assistant-ui，完整接入文字、图片和附件。文件选择、拖放与粘贴进入同一上传流程；显示进度、失败原因及移除操作。图片可缩略预览和放大，文件可按本人权限下载；消息与附件刷新后可恢复。Markdown、代码块、表格与复制、历史加载、停止与稳定请求重试属于此次交互范围。文件内容实际进入模型可处理的输入；模型未启用视觉或文档无法提取时必须明确显示，不把文件名当作已读内容。

首期支持文字、附件和业务对象引用；语音、角色动画、复杂人格配置不作为首期依赖。视觉风格复用现有 Mantine、主题与中文术语，清爽、低装饰，支持键盘操作与屏幕阅读器。

## 3. 伙伴如何持续工作

### 3.1 工作来源

| 来源 | 示例 | 行为 |
|---|---|---|
| 用户交办 | “把这笔采购的验收资料整理好。” | 明确目标和范围，执行可执行步骤 |
| 业务事件 | 附件上传、收货更新、审批完成 | 找到相关在途任务，更新判断并继续推进 |
| 定时检查 | 检查已授权范围内未归档收货 | 查询实际状态，只对新变化采取行动 |
| 等待条件满足 | 缺失的签字已由本人完成 | 重新校验前置条件，续接原任务 |

“常驻”指服务和工作责任持续存在，工作不依赖浏览器或聊天连接；空闲或等待期间无需不停调用模型。长时间没有业务变化时保持安静。

助手不会凭自己推测获得对全仓业务的权限。初次启用时通过自然语言和精简设置确定工作范围；管理员可配置允许的默认只读职责。临时明确命令授予该次任务范围，持续职责需要明确的长期授权。暂停、撤销、修改均可通过对话或更多菜单完成，当前授权可随时查询。

### 3.2 第一条完整常驻职责

首期以“入库验收与归档跟进”为推荐完整切片，对应 IN-01～IN-06：

1. 用户指定采购单集合或仓区，并明确可查询、整理及执行的动作。
2. 伙伴持续发现范围内的收货、验收、附件和处置状态变化。
3. 自动核对采购关联、检验记录、照片与验收单、必要签字和异常分支。
4. 对已授权且系统支持的操作直接执行，例如关联明确归属的附件；不确定的照片归属需要询问。
5. 缺失检验结论、签字或审批时，保留等待状态，并用对话说明需要什么。
6. 条件满足后自动续接；最终依据业务记录给出结果与链接，未满足完整闭环时不称“归档完成”。

这条职责应覆盖“无人聊天期间出现变化 → 自主处理 → 必要消息 → 重启恢复”的完整链路。不能仅用页面轮询、定时固定文案或模型模拟成功代替常驻能力。

### 3.3 主动消息

只有需要用户行动、发生实质异常、完成有价值的任务或执行失败时主动发消息。周期检查无变化不发消息，重复事件合并，同一问题不每次检查都催一次。

首期消息只写入仓序内的本人对话与未读状态。邮件、短信、企业聊天或联系供应商需另行授权与渠道设计，当前规划不包含自动外发。

“提醒静音”“暂停某项职责”“停止当前操作”“停止全部自主写入”是不同动作，必须准确执行并回复作用范围。撤销自动写入授权后，不因重启、重新登录或新事件自动恢复。

## 4. 知识与能力覆盖

2026-10-13 最新实施顺序：优先把现有业务 API 包装为模型可调用工具，覆盖物料/SN、库存、采购收货、工单/BOM、实装配置、质量、维修、交付、盘点及附件，再补网站和流程知识。沿用当前登录及业务权限，用户交办后直接推进；grant 不是模型工具的前置配置项。命令回执、去重和停止资格是后台可靠执行机制，不是新增的用户审批流程。本人签字、检验和业务审批仍按原流程处理。

### 4.1 全流程知识

知识目标覆盖网站导航、页面字段、权限解释、状态含义、常见报错，以及入库、领退料、装配、质量返工、供应商维修、交付签收、盘点和导入的完整操作知识。

每个流程的知识条目包含：适用角色、前置条件、操作步骤、异常分支、签字/审批、归档证据、相关页面、资料版本和系统支持边界。正式流程图和表单均需纳入，不能因当前无页面就省略相应业务要求。

| 内容 | 权威来源 | 回答要求 |
|---|---|---|
| 网站用法 | 当前网站的经过维护的操作说明与页面目录 | 可定位到现有页面，不能编造入口 |
| 正式规则 | 业务确认的 SOP、验收表、批准的工程资料 | 引用有效版本；规划文件不能冒充已生效制度 |
| 库存与订单事实 | 实时业务 API | 标明必要的查询时间；数量使用确定性业务计算 |
| 个人偏好 | 用户明确表达并允许保存的信息 | 可查看、更正、删除；不替代业务事实 |

知识管理员负责发布、更新、撤回和处理缺失条目。检索结果、附件和历史消息必须遵守权限；不能把其他用户的对话当作公共知识。

### 4.2 知道与执行分别验收

| 业务范围 | 首期知识目标 | 执行开放条件 |
|---|---|---|
| 入库 IN-01～IN-06 | 覆盖采购关联、验收、可选隔离、附件、单步处置 | 首期完整切片，逐动作接入与验收 |
| 领退料 MAT-01～MAT-02 | 区分备料、预留、耗材领退和装配件拆回 | 优先接已有耗材领退接口；并发与数量守恒通过后开放 |
| 装配 MFG、质量 QC | 覆盖配置版本、换件复测与放行要求 | 随业务闭环开放；未实现的正式放行禁止伪装可执行 |
| 售后 RMA | 覆盖所有权、外送、部分返还及换 SN | 逐业务动作验收；未返和所有权不明不得自动结案 |
| 交付 OUT | 覆盖分批交付、装箱、签收差异 | 优先签收登记；补发和库存纠正规则确认后再接入 |
| 盘点 INV、导入 DATA/INT | 覆盖核实、复核、暂存、冲突与权威边界 | 先只读分析和准备；不凭历史台账或差异猜测自动改账 |

## 5. 自主执行与人工责任

明确命令中对象、动作、数量和范围充分，且用户有权执行时，连续完成已授权步骤，不增加逐按钮确认。持续职责中的写入按已批准范围执行，不每次重新询问。

2026-10-13 补充确认：让 agent 持续推进，禁止把后台授权模型变成反复打断工作的产品流程。用户自然语言交办即为相应任务的执行依据，由系统自动记录范围和来源；不要求用户逐工具创建 grant、重复批准计划或每一步点击“允许”。常驻职责在设定或实质改变范围时一次登记，后续事件、定时检查、重试和重启恢复沿用。应用角色权限与业务本人签字/审批仍由后端执行；有独立可行步骤时继续推进，不把局部缺失扩散为整项工作阻塞。

只有以下情况需要停在相应步骤：必要信息缺失、对象歧义、范围实质变化、权限不足、业务冲突，或业务本身要求检验、签字、批准。伙伴应一次说明所需信息，其他无依赖工作可继续。

必须保持的业务规则：

- InvenTree/仓序是唯一库存业务账，助手不得维护或回写第二套库存余额。
- 默认正常可用收货、可选隔离、异常验收转隔离及正常/让步/退回分支均遵循 IN-01～IN-06；技术/采购意见不阻塞单步处置。
- 不能代替本人验货、实盘、签字，不能编造照片、SN、兼容关系或工程批准。
- 同 SN 跨物料歧义、套件数量未确认、权限撤回、旧测试不适用等情况必须显式处理。
- 失败或停止后准确报告已生效和未生效部分；已提交业务变更的撤销使用正式更正流程。

## 6. 交付范围与完成定义

### 第一版必须同时具备

- 简洁独立对话页、右下角入口、连续历史、附件与业务引用。
- Pi Durable 持久运行、关闭浏览器后执行、启动恢复。
- 业务事件与定时检查两种主动触发；入库归档常驻职责完整闭环。
- 全流程知识目录与代表性有效内容；未提供正式资料的条目明确标记缺口。
- 实时业务查询、至少一条真实业务写入路径、后端权限及幂等保障。
- 对话内必要通知、输入补充、人工业务动作与失败恢复。
- 可查询/撤销的授权、可管理的个人记忆、成本和运行限制。

内部可以分阶段实现，但对外不得把仅有聊天壳或只读问答称为本规划的第一版完成。全流程知识覆盖与所有流程自动执行是两个独立验收维度。

### 后续扩展

逐步开放领退料、签收差异、装配返工、维修、盘点和导入的执行工具；每项先完成底层业务规则与验收。团队共享伙伴、多渠道联系、语音和高可用多实例部署另行规划，不作为首期 UI 的复杂化理由。

## 7. 验收方式

需求编号为 AI-01～AI-12，详见[需求基线第 6.1 节](REQUIREMENTS.zh-CN.md#61-常驻工作伙伴)。可执行验收场景见[技术规划第 12 节](ASSISTANT-TECHNICAL.zh-CN.md#12-验收场景与证据)。

产品验收必须包含实际操作员从同一个简洁对话中完成：交办、离开网站、等待资料补充、返回看到自主结果、查看业务记录、继续处理。另由操作员按最新截图确认左侧伙伴列表、右侧连续对话和固定输入条；手机端可在列表与对话之间切换，页面不演变为任务看板。
